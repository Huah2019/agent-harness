# CLI 使用日志（维护者说明）

CLI 自动记录调用，Agent 的命令、输出及有用反馈流程不变。日志只用于后续分析，不进入知识库、上下文或热点计数。实现使用 Timberjack v1.4.7；不自建轮转、压缩及归档清理算法。

## 存储与保留

默认目录：`~/.local/state/agent-wiki/<知识库真实路径的 SHA256 前 16 字节>/`。目录权限 0700，事件文件 0600。通过 `logs --status` 查看当前知识库的准确目录。

- 活跃文件 `events.jsonl`，单文件 4 MiB，按大小轮转。
- 归档 gzip 压缩，最多 15 份，按归档名时间保留 180 天。
- 年龄/份数清理由库在打开或轮转时触发，退出前等待维护完成。不运行 CLI 时不执行清理，也不会增长。
- `MaxAge` 是归档年龄，不是每条事件 TTL；活跃文件不会按日期轮转。
- 容量由单文件大小和份数约束，不承诺严格的目录字节配额；压缩临时文件可能短暂增加占用。
- 单条事件最多 8 KiB；参数、错误、对象列表超限截断，记录 `truncated`。

维护者可设置 `AGENT_WIKI_LOG_DIR` 指定状态基目录，或 `AGENT_WIKI_LOG_DISABLED=1` 禁用记录。常规 Agent 无需设置。

## 事件语义

每次取得知识库锁的命令记录一条事件：schema、event_id、UTC 时间、command、有限参数、outcome、耗时，以及明确条目的 ID、路径、前后 SHA256 和有用计数。`use` 原有 reason 包含在参数中。`run rg` 的退出码 1 记作 `no_match`，不改变原命令退出行为。

明确指定的 Markdown 文件记录快照；目录搜索只记请求范围，不把搜索命中解释成阅读。patch 比较执行前后条目快照，仅保留变化对象（最多检查 128 个条目，超限标记）。正文、输出和 stdin patch 不写入日志。单文件快照限 5 MiB；hash 包含 frontmatter，因此反馈更新也会改变 hash。没有采集会话上下文或推断任务 ID。

首次启用前的累计次数不补造成历史事件。`used_count` 仍由原有知识库逻辑维护，不依赖日志重算。日志不是事务审计：CLI 被强杀、写入失败时可能缺记录；“读取”也不等于“有用”。

## 进程与故障

外层 CLI 在现有知识库进程锁内采集事件，调用自身内部写入进程，等待 Timberjack Close 排空维护，再释放锁。这样同一知识库只有一个写入/清理进程。内部进程最多运行 5 秒，不创建常驻服务；其输出与原命令隔离。

写入失败或库诊断写入固定大小 `last-error.json`（覆盖上一条，不无限累积）。日志根目录本身不可写时，该状态也无法写入。此文件表示最近一次观察到的错误，不表示错误后没有恢复。解析根目录或取得锁之前的失败无法记录。内部写入参数是实现细节，不应手动调用。

## 按需分析

```bash
./bin/agent-wiki logs --status
./bin/agent-wiki logs --since 2026-09-08 --command use --limit 1000
./bin/agent-wiki logs --since 2026-09-07T16:00:00Z --command run
```

日期参数按 UTC 零点解析；北京时间某日使用前一天 16:00Z。输出为 JSONL，按归档文件名顺序读取、活跃文件最后；默认最多 1000 条，并非最近 1000 条。查询逐行解压，日志查询自身不记事件。损坏数据明确报错，不静默计作零。统计时注明查询时区、limit、保留范围及 last-error，不能把缺记录当作没有使用。
