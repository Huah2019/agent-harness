# 当前演进队列

本项目的近期目标是把 `agent-wiki` 从一个可用的受控 Markdown 知识库,推进成能帮助 agent 持续改进项目的工作记忆系统。

## 当前优先级

1. 明确知识沉淀边界:让 skill 说明什么信息应该进入知识库,什么信息不应该进入知识库,但不固定项目目录结构。
2. 建立项目级工作闭环:agent 进入项目时先读上下文和相关知识,完成任务后反思是否需要沉淀新判断、常见坑、验证流程或演进方向。
3. 补齐可复用操作手册:把开发、验证、挂载和收尾流程写成薄 runbook,减少每次重新推断。
4. 后续再改进 CLI 体验:优先考虑 `show`、`search`、`roadmap`、`reflect`、`doctor` 等命令,降低直接使用 `run sed/rg` 的心智负担。

## 暂不优先

- 不先做 RAG、数据库或 MCP 服务化。
- 不把所有项目资料搬进知识库。
- 不把目录结构设计成强约束;目录可以按项目自然扩展,核心约束由 `SKILL.md` 的沉淀标准承担。

## 判断标准

一次演进是否值得做,看它是否能让下一次 agent 更快、更稳地完成项目任务。如果只是增加包装、索引或流程感,但不改变 agent 的实际判断和行动,就应该暂缓。
