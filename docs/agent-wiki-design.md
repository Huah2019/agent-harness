# agent-wiki 整体设计

本文是 agent-wiki 的整体设计入口，持续维护目标、知识模型、上下文、反馈、存储与
操作边界。由 README 提供入口，不在 Skill 中注册，也不注入 Agent 启动上下文。
日常操作协议留在 SKILL.md；设计变化更新本文，不再为每个功能复制一套设计说明。

## 1. 目标与非目标

agent-wiki 为 Agent 提供可维护的项目工作记忆：先发现相关知识，再按需读取，
用当前代码和证据校验，并将真正可复用的判断写回。目标不是尽可能多地保存内容，
而是让下一次任务少走弯路、保留项目边界和长期决策。

- 保留：项目定位、设计取舍、可复用流程、常见坑、验证入口、演进方向与废弃方案。
- 不默认保留：任务流水账、代码副本、大段日志、未经验证却写成事实的猜测。
- 不以数据库、向量检索或 RAG 为前提；当前以 Markdown 和受控 CLI 完成闭环。
- 知识不是事实裁判：与当前代码、运行结果或用户最新要求冲突时，应核实并更新知识。

## 2. 架构与职责

```text
宿主项目通过 .agents/skills 暴露 Skill
  → Agent 按 Skill 的操作协议调用 Go CLI
  → CLI 解析 wiki_root，读写 Markdown 源数据
  → CLI 从元数据生成 AGENT_CONTEXT.md
  → 宿主按自身机制加载入口，Agent 按需读取正文与引用资料
```

| 层 | 职责 | 不承担 |
| --- | --- | --- |
| README、docs/ | 面向维护者的安装入口、整体设计和实现边界 | 不自动成为 Agent 上下文 |
| SKILL.md | 何时查阅、如何操作、何时记有用、如何收尾 | 不承载整体实现设计与业务知识正文 |
| Go CLI | 路径与格式约束、受控读写、反馈、索引生成和校验 | 不判断业务结论真假 |
| Markdown 知识库 | 可读、可 diff、可版本管理的权威源数据 | 不充当日志仓库或代码镜像 |
| AGENT_CONTEXT.md | 从源数据生成的发现入口 | 不存放正文副本，不手工维护生成区 |

Skill 与知识库分离，可将同一个 Skill 挂到不同项目并绑定不同知识库。
根目录优先由 `--root` 指定，其次为 `AGENT_WIKI_ROOT`，否则走 Skill 配置及默认定位。
配置中的相对 `wiki_root` 按真实 Skill 目录解析，不按调用项目的工作目录解析；
本机配置不提交。仓库自带 `agent-wiki/default-wiki`，测试该库时显式传 `--root`。
CLI 负责生成/输出上下文，不依赖全局 hook，也不替宿主决定如何注入上下文。

## 3. 知识模型与上下文

知识目录通过 `.meta.yaml` 声明 `id/title/summary`，目录按项目自然演进，
不强制统一业务分类。普通知识文件是一条原子知识，文件名采用 kebab-case。

知识 frontmatter 保存：

- 身份与摘要：`id`、`title`、`summary`；移动保留身份。摘要用于发现，正文解释判断。
- 内容日期：`created`、`updated`；修改内容更新 `updated`。
- 有用反馈：`used_count`、`last_used`、`last_used_at`、`last_used_reason`。

`context_mode` 目前只是预留字段，不应当作已实现的隐藏或正文展开机制。
引用资料单独存放，详见下一节；它不是另一类参与排名的知识。

发现和读取分层：

1. `context` 输出生成入口：一级目录、有用反馈 Top 20、最近更新 Top 10、最近反馈有用 Top 10。
2. `map` 默认展开一层目录与摘要；需要时指定路径和深度，不读取全部正文。
3. `run rg` 搜索知识，`run cat/sed/nl` 读取选中的正文。
4. 读到引用关系后，按知识说明的条件读取相关资料，不递归预加载。

热点按 `used_count` 降序；最近内容按 `updated` 降序；最近有用按 `last_used_at`
降序，兼容旧 `last_used`。同值时按路径排序。引用资料不参与以上扫描和默认搜索。
榜单是低成本发现启发式，不是质量分数或事实可信度，也没有自动衰减和淘汰机制。

## 4. 引用文档

### 为什么拆分

知识条目是决策入口，资料清单、案例细节不是独立的决策入口。把两者都注册为知识，
会让频繁更新的清单挤占上下文，并产生没有意义的“有用次数”。
因此，引用文档的用途由引用它的知识说明，不独立排名或自动升级为知识。

### 数据与发现边界

| 对象 | 知识条目 | 引用文档 |
| --- | --- | --- |
| 存储 | 知识目录下的 Markdown | `references/` 及其子目录中的 Markdown |
| 元数据 | frontmatter、摘要、有用反馈 | 非空普通 Markdown，无知识 frontmatter |
| 目录描述 | `.meta.yaml` | 不允许注册 `.meta.yaml` |
| 发现方式 | map、启动上下文、榜单、搜索 | 从正文相对链接按需读取；显式指定目录搜索 |
| 更新 | 更新 `updated` | 不添加或更新知识元数据 |
| 反馈 | `use` | 拒绝 `use`，不计数 |

正文可维护更新时间、负责人等业务信息，但 CLI 不强制这些字段。
`references` 是保留路径组件，可位于任意知识分类下。多个知识可以共享同一份资料，
不要求登记单一父节点；链接及其周围的文字就是用途与读取条件。

例如知识正文写：

```markdown
维护引用资料时，先读 [维护清单](./references/reference-maintenance-example.md)，
确认读取入口、链接和资料状态；不要把清单全文复制进知识摘要。
```

引用文档可以继续引用资料，但读取不会递归预加载。`run ls/find` 仍可检查文件系统；
不注册上下文是发现策略，不是权限隔离或保密机制。

### 引用生命周期与链接边界

- `ref add` 创建资料；再通过 `patch` 在知识正文补链接和使用条件。
- `run cat/sed` 按需读取；`patch` 编辑，引用文档不获得知识元数据。
- `ref move` 更新库内指向它的链接，并重定位被移动文档自身的相对链接。
- `ref remove` 遇到其他文档的入链就拒绝；先明确修改引用方，再删除。
- `check` 对可识别的库内 Markdown 文档断链报错，对没有入链的引用文档仅警告。
  不按访问次数清理，不自动删除孤立文件；互相引用的孤立环目前不做可达性检查。
- 普通知识的 `move/remove` 沿用已有实现，不承诺与 `ref move/remove` 相同的链接修复能力；
  调整知识入口后应处理相关链接并执行 `check`。

链接处理支持普通内联链接、图片链接和引用式定义，以及角括号目标、锚点和查询参数。
代码示例和 HTML 注释不参与改写。外部 URL、绝对路径、页面内锚点不作为库内依赖；
不验证外链可达性或标题锚点是否存在。当前是有限语法扫描，不是完整 CommonMark 解析器，
HTML 链接、复杂嵌套链接不能作为受管理引用。

## 5. 操作与一致性

Agent 通过 CLI 操作知识库，不能绕开协议直接修改文件：

- `add/use/move/remove` 管理知识；`ref add/move/remove` 管理引用资料。
- `patch` 只修改已有 Markdown，不直接修改目录元数据或生成上下文。
- `run` 只允许受控只读命令，不经过 shell 执行；拒绝越界路径和 shell 元字符。
- `check` 校验目录元数据、知识格式、引用链接、符号链接和补丁残留；不证明内容正确。
- `clean` 将补丁残留备份到库外再清理，不自动合并失败补丁。

CLI 按规范化知识库路径加进程锁。`patch` 和引用写入在临时副本应用修改、刷新上下文并
校验，提交前检查待改原文是否变化，提交错误时尝试回滚。其他知识命令沿用原有顺序写入，
不承诺所有命令均有同等事务保护。单文件原子替换也不等于跨文件事务，崩溃或掉电仍需检查恢复。
CLI 约束不替代系统文件权限，也不能约束其他进程绕开 CLI 直接写文件。

## 6. 有用反馈、运行记录与维护闭环

“读取”和“有用”必须分开：读取不加分；知识实际影响判断、回答或改动时，才用
`use --reason` 增加计数并记录时间和原因。反馈更新不改变内容 `updated`。
引用文档不计有用次数，其用途由引用它的知识决定。

任务结束后判断是否形成长期结论：有则新增、修订或删除过时知识，并运行 `check`；
没有就不沉淀。自动生成索引不是自动生成知识；是否记录、是否修订仍需要证据和判断。

CLI 另有本地有界运行日志，用于排查命令执行，不参与知识排名：

- 记录命令、有限长度参数、结果和耗时；部分知识操作记录文件摘要与计数变化。
- 搜索命中不等于逐个读过；引用文件目前不纳入知识对象快照，日志不是完整文件审计。
- 默认写在知识库外的用户状态目录，按库隔离；单文件 4 MiB、最多 15 份备份、最长 180 天。
- 可通过 `AGENT_WIKI_LOG_DIR` 指定位置，或 `AGENT_WIKI_LOG_DISABLED=1` 关闭。
- `logs` 是维护者查询入口，不纳入 Skill 工作流；日志错误不应使业务命令失败。

日志不保存正文快照，但参数/错误可能含搜索词、反馈原因和路径，不能视为完全脱敏数据。

## 7. 设计维护与验证

整体模型、边界和取舍变化更新本文；Agent 操作约定变化再更新 Skill；
README 只维护导航和基本用法，default-wiki 只保留对后续判断有价值的薄知识和示例。
同一机制不在多个文档维护相互竞争的完整说明。

- 核心实现：`skills/agent-wiki/cmd/agent-wiki/main.go`，配置、命令、知识扫描、反馈和上下文。
- 引用资料：同目录 `references.go`；运行记录：`usage.go`。
- 对应测试：`main_test.go`、`references_test.go`、`usage_test.go`。
- 默认库中的示例仅展示组织方式，不记录真实用户资产或环境配置。

修改后运行 `go test ./...`、`go vet ./...`，重建 CLI，并对默认库执行 `check`。
用 `map/context` 确认引用资料未独立暴露，再从知识正文沿链接读取示例。
